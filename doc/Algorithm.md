当前是如何实现时间序列划分的？**batch size 16**、**BiGRU** 和**实时监测**这三个问题我分开讲清楚。

### 1. batch size 16 是什么意思？

**batch size** 是训练时一次同时喂给模型的样本数量。

- `batch size = 16` 就是每次训练迭代，同时处理 **16 个视频**（或 16 段序列）的数据。
- 它和“16 帧”完全无关。
- 作用主要是：加速训练、稳定梯度、提高 GPU 利用率。
- 越大越占显存，但训练通常更稳定；太小则训练慢、波动大。

这是一个**训练超参数**，不影响模型最终输入输出的定义。

### 2. 用 BiGRU 在整个时间序列上建模时序依赖，是什么意思？

模型处理的是**一整个视频的时间序列**（不是固定 16 帧）。

流程大致是：

1. 每一帧都先提取人和物体的特征（几何 + 视觉融合后的实体特征）。
2. 这些特征按时间顺序排成一条序列（长度为该视频的帧数 \( T \)）。
3. 把这条序列送进 **BiGRU**（双向门控循环单元）。
4. BiGRU 会从前往后看一遍，再从后往前看一遍，从而捕捉这段时间内动作的前后依赖关系。
5. 最后输出整段视频的分割结果和标签。

**关于序列长度能不能自己设：**

- 原模型设计上是处理**完整视频**（长度可变），不是强制固定长度。
- 实际训练时，代码里通常会对不同长度的视频做**填充（padding）**或截断，方便组成 batch。
- 如果你自己改代码，理论上可以改成固定长度（比如每次只取 64 帧、128 帧），但那已经不是原论文的设定了，需要自己改数据加载和模型部分。

### 3. 如果想做实时监测，怎么办？

**原版 GeoVis-GNN 不适合直接做实时。** 主要原因：

- 它用的是 **BiGRU**（双向），必须看完整段序列才能计算，属于**离线**模型。
- 它是针对整段视频做分割和识别的，不是逐帧在线输出。

如果要实现**实时监测**，需要做改造，常见做法有：

| 方案 | 说明 | 优缺点 |
| ------ | ------ | -------- |
| **滑动窗口** | 每隔一段时间取最近 N 帧（比如最近 2～4 秒）送进模型 | 实现简单，延迟可控，但窗口边界可能不准 |
| **改成单向 GRU / LSTM** | 把 BiGRU 改成单向，只能看过去，不看未来 | 可以在线运行，但精度通常会下降 |
| **流式处理** | 每来一帧就更新状态，输出当前判断 | 延迟最低，但需要较大改动，且原模型没有为这个设计 |
| **轻量替代方案** | 用纯骨架的实时动作识别模型（如基于 MediaPipe + 轻量分类器） | 实时性好，但不是 GeoVis-GNN 的 HOI 能力 |

### 总结建议

- **batch size 16**：只是训练时一次处理 16 个视频，和帧数无关。
- **BiGRU**：用来在整段视频上捕捉时间前后关系，原模型是离线的。
- **实时监测**：原模型不直接支持，需要改成滑动窗口或单向网络，会损失一些精度，且要自己改代码。

类别告诉模型“对象是什么”，关键点和时序告诉模型“它怎么运动、和人是什么关系”。 模型通过动作标签学习如何组合这些信息，而不是写死“杯子就是喝水”。

                         ↓

YOLO 类别与关键点是输入，不是动作标签。 仍然需要你标注“写字、喝水、拿起”等活动。
如果希望分别输出物体可供性，还需要额外标注对应物体标签，并启用物体分类输出：
总损失 = 人的动作分类损失 + 加权的物体分类损失
如果做逐帧分割，则要使用时间区间/逐帧标签，而不是继续给整个窗口一个标签。
必须避免“看到杯子就预测喝水”
训练中要包含：

- 同一物体的多种动作。
- 同一动作作用于不同物体。
- 物体出现但目标动作未发生的负样本。
否则显式类别也可能变成模型偷懒的线索。

3. 和完整 GeoVis-GNN 相比，预计怎样？
完全独立的两路模型，相当于削弱了 GeoVis-GNN 的一个核心优势：人的动作与物体可供性相互提供证据。
联合建模：
手向杯子伸去 + 杯子的位置 → 帮助判断交互

独立建模：
人体路只看到伸手
物体路只看到杯子静止

- 标签主要由自身决定：独立建模可能已足够，计算也可能减少。
- 标签依赖人与物体关系：预计更容易混淆，联合建模通常更合适。
- 具体精度下降多少：不能可靠给出百分比，需要同一数据集上的消融实验。
结论：人体独立识别子活动，完全可行；物体独立识别状态或部分可供性，也可行。但关系型可供性和精细交互动作，切断人体—物体信息后会存在明显的信息缺口。

人体关键点 + 人体外观 -> 时序与交互建模 -> 人的子活动
